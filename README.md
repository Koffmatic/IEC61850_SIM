# IEC 61850 MMS IED Simulator

This repository contains a Windows-oriented IEC 61850 MMS simulator package for testing Moxa MGate 5119 and similar MMS clients. The package focuses on IEC 61850 MMS server simulation. It does not implement Modbus TCP bridging or GOOSE publishing.

The main user interface is a local browser-based launcher. It manages relay rows, writes runtime JSON files, prepares Windows IP aliases, and starts the bundled MMS server executable.

## Repository layout

- `IEC61850_IED_Sim_Launcher.py`
  - thin entrypoint that starts the local browser launcher service
- `launcher_service.py`
  - local HTTP service and browser UI
  - persists launcher state under `%LOCALAPPDATA%\Koffmatic\IEDsimulator\runtime`
  - writes relay-specific `*_config.json`, `*_values.json`, and `*_server.log` files
  - launches the packaged MMS server executable from the fixed path `./ied_mms_server.exe`
- `src/ied_mms_server.c`
  - IEC 61850 MMS server implementation used by the packaged executable
  - supports runtime `--ied-name`, relay type selection, bind IP, port, and values JSON updates
- `generated/`
  - generated static models for REF615, REU615, and RED615
- `tools/add_ip_aliases.ps1`
  - PowerShell helper generated by the launcher for adding required IPv4 aliases to the selected adapter
- `vendor/libiec61850`
  - vendored libIEC61850 source used by the CMake build

## Requirements

- Windows
- Python 3 for the launcher
- No external Python packages are required for the browser-based launcher
- Administrator rights are required when adding IP aliases to a network adapter

## Launching the browser UI

Start the launcher from the repository root:

```powershell
py IEC61850_IED_Sim_Launcher.py
```

By default, the service listens on `http://127.0.0.1:8787` and opens the browser automatically.

You can override the host, port, or browser launch behavior:

```powershell
py IEC61850_IED_Sim_Launcher.py --host 127.0.0.1 --port 8794 --no-browser
```

If the service is already running on the selected localhost address, a new launcher instance reuses the existing service instead of starting a second copy.

## What the launcher does

The browser UI lets you:

- add and remove relay rows
- edit relay `Name`, `IED key`, relay type, bind IP, and port
- edit analog, word, and boolean tag lists per relay
- edit live values and write them directly to runtime JSON
- start or stop a single relay or all enabled relays
- enable continuous random value updates
- regenerate the IP alias PowerShell script
- prepare the selected network adapter for multi-IED testing
- show when a relay IP alias is missing on the selected adapter

The executable path is no longer user-editable in the UI. The launcher always starts the packaged MMS server from:

```text
./ied_mms_server.exe
```

## Default relay inventory

If no saved launcher state exists yet, the launcher creates these default relay rows:

- 11 x `REF615` on `10.206.204.5` through `10.206.204.15`
- 2 x `REU615` on `10.206.204.16` and `10.206.204.17`
- 1 x `RED615` on `10.206.204.18`

The default names start as `REF615_SIM_01` through `REF615_SIM_11`, `REU615_SIM_01`, `REU615_SIM_02`, and `RED615_SIM_01`.

The actual row list is persisted, so once the user renames rows or changes IP addresses, those values are restored from the saved launcher state.

## Runtime files

The launcher stores user-specific runtime data under:

```text
%LOCALAPPDATA%\Koffmatic\IEDsimulator\
```

Important files and directories:

- `runtime\launcher_state.json`
  - persisted browser launcher state
- `runtime\<ROW_NAME>_config.json`
  - relay runtime configuration
- `runtime\<ROW_NAME>_values.json`
  - live relay values used by the MMS server
- `runtime\<ROW_NAME>_server.log`
  - per-relay process log
- `tools\add_ip_aliases.ps1`
  - generated PowerShell helper for adding missing adapter IP aliases

The launcher also removes stale runtime files that no longer belong to any configured relay row.

## Network preparation on Windows

Each simulated IED must bind to its own local IPv4 address. For a single Windows machine hosting multiple MMS servers, add multiple IPv4 aliases to the same physical adapter.

Use the `Prepare network` button in the browser UI to:

- regenerate `add_ip_aliases.ps1` for the currently configured relay IPs
- launch the script in an elevated PowerShell window

The generated script targets the currently selected adapter and keeps the PowerShell window open briefly so its output is visible.

You can also run the generated script manually in an elevated PowerShell session:

```powershell
powershell -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\Koffmatic\IEDsimulator\tools\add_ip_aliases.ps1"
```

If a relay row shows that its IP alias is missing, the MMS server will fail to bind until that IP exists on the selected adapter.

## Runtime JSON format

Each relay values file follows this structure:

```json
{
  "analogs": {
    "LD0.CMMXU1.A.phsA.instCVal.mag.f": 18.4
  },
  "bools": {
    "LD0.LEDGGIO1.Ind1.stVal": true
  },
  "words": {
    "LD0.SSCBR1.Beh.stVal": 1
  },
  "updated_unix_ms": 1715420000000
}
```

The MMS server is launched in this form:

```text
ied_mms_server.exe --ied-name <ied_key> --type <relay_type> --bind <ip> --port <port> --values <values_json_path>
```

The launcher writes both the display name and the protocol-facing IED name to each relay config JSON.

## Building the MMS server

The repository includes a CMake project that builds the C server against the vendored libIEC61850 source.

Configure and build from the repository root:

```powershell
cmake -S . -B build\real
cmake --build build\real --config Release
```

The CMake target name is:

```text
ied_mms_server
```

The build uses:

- `src/ied_mms_server.c`
- `generated/ref615_static_model.c`
- `generated/reu615_static_model.c`
- `generated/red615_static_model.c`
- `vendor/libiec61850`

## Notes

- Port `102` is the intended default for MMS testing.
- The launcher can still write JSON and helper scripts even if the executable is missing, but relay start will fail with `missing exe`.
- Row changes to name, relay type, bind IP, or port require restarting that relay process before the running instance reflects the new values.

## Building a Windows installer

Do not chain `PyInstaller` and `ISCC` into one command. They are separate tools and must be run as separate steps.

The recommended way is to use the included PowerShell build script:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_windows_installer.ps1
```

What the script does:

- builds the launcher bundle with PyInstaller into `dist-build\IEC61850_IED_Sim_Launcher`
- avoids the locked `dist\IEC61850_IED_Sim_Launcher` cleanup problem by using a separate build output directory
- prompts for installer version changes with defaults `major=no`, `minor=no`, `patch=yes`
- falls back to those defaults automatically in non-interactive runs that cannot answer prompts
- tries to locate `ISCC.exe` from `PATH` or common Inno Setup install locations
- compiles the installer from `build\installer\IEDSimulator.iss`

If Inno Setup is not installed yet, you can still build just the launcher bundle:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_windows_installer.ps1 -SkipInstaller
```

After installing Inno Setup 6, run the same script again without `-SkipInstaller` to produce the final installer in `dist-installer`.

You can also bypass the version prompt explicitly:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_windows_installer.ps1 -NoVersionPrompt
```
